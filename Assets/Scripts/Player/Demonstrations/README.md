# Player demonstrations

`Assets/Prefabs/PlayerActor.prefab` is the shared, single-player source. The four actors in `Players.prefab` are nested instances of it; `Players_Gameplay.prefab` continues to supply the gameplay roster. How To Play spawns the same source at runtime. Make common component, collider, visual and ability changes on **PlayerActor**, and balance changes in **MASSIVE > Player Tuning**. Changes made only as overrides on one scene/roster instance remain local to that instance.

The old `Player.prefab` and `Pseudo Player 1/3.prefab` are legacy assets. The old How To Play pseudo instances are retained inactive for reference. Do not use these copies as the source for new demonstrations.

Gameplay spawn anchors belong to each nested slot in `Players.prefab`; the standalone Actor has no roster anchor. Scene overrides bind goals and grids, and each `PlayerRosterController` explicitly references its four scene instances. Converting the roster to nested Actors changes prefab-local object IDs: preserve the per-slot anchors and remap consumer references, including variant IDs, rather than relying on runtime discovery. `PlayerActorReferenceMigration` captures those identities before conversion. Unity missing-object references must be checked with Unity's null semantics, not C# null-coalescing.

Match startup validates the selected mode's required slots (normally P1/P3 for 1v1, all four for 2v2). Each needs a unique scene-local match player with the correct ID, an enabled controller, a roster spawn anchor and a goal. Required players must be active after roster activation. Automatic discovery only repairs unambiguous missing slots. A failed check logs one error naming the scene, roster, slot and failed binding; `StartupFailureReason` exposes the diagnostic on the roster and match manager. The match stays in Preparing with scoring and input locked, including when spawn waiting is disabled. Fix the binding and reload the scene; rejection is latched to prevent a partially initialized match from resuming.

## Policy and input

`ConfigureDemonstration` runs before the actor becomes active. It selects scripted input, shared gameplay tuning and a non-match role. This preserves ordinary movement, combat, shield, size/reversal and power-up behavior while excluding match scoring, HUD and spawn presentation. `IsPseudoPlayer` remains the compatibility flag for existing match filters; tuning is now a separate `PlayerTuningMode` policy. Automatic keeps legacy fixtures local; SharedGameplay opts demonstrations into live values; Local is an explicit fixture override.

Every action goes through `PlayerInputFrame`, including attack press, hold and release. Directional aim is explicit, so stationary actors can face each other. Control graphics observe applied input and cannot delay actions.

## How To Play audio

The shipped route is Attract / mode selection → `S-0_HOW-TO-PLAY-PANES` → level selection → stage instructions → gameplay → results → Attract. `SceneFlow.HowToPlayScene` and enabled build index 1 select the carousel scene. The original `S-0_HOW-TO-PLAY` scene remains unchanged for safekeeping, with a disabled Build Settings entry. Attract's persistent BGM manager retains the original music mapping and also maps the carousel scene to the same menu profile.

How To Play is SFX-silent for its entire scene lifetime. Its existing screen controller acquires `SceneSfxPolicy` before the actors start; disabling the continue/input controller does not lift the silence. AudioSystem, SfxBus and the legacy fallback reject SFX requests. Listener pause also silences ordinary AudioSources and play-on-awake effects added to future prefabs. Keep `ignoreListenerPause` reserved for music; BGMManager and MusicPlayer register their sources explicitly. No actor/power-up prefab needs a special mute override.

Leaving the scene clears queued SFX and pool cooldown/concurrency state, then restores the prior listener and music-source settings. Shared clip volumes, music playback and gameplay SFX settings are preserved. Other demo/test scenes retain their usual audio.

## Scenarios

Create a **MASSIVE > Demonstrations > Player Scenario** asset and assign PlayerActor. Attach `PlayerDemoDirector` to a stage, then assign the scenario. Optional camera and control graphics only affect presentation.

- Movement and combo moves using actual propulsion and advances through the live combo engagement windows.
- Block shares one director for both actors. It derives spacing and shield timing from the live attack/shield data, and waits for real shield contact before counting success.
- Amplifier Goal gives the canonical actor an actual 16x personal score chain, then uses Thrust entry, charged input, the normal Core shot/capture, and native Core respawn. The scene uses a cropped instance of the canonical TeamGoals_Planar team goal, including its native metaball surface, shared Amplifier treatments/grid effects and goal-number animation. Scoped display providers show the team increase without changing live match multipliers; the personal multiplier is shown by its normal shimmer, without a separate caption. Multiplier shimmer reads the shared settings for simulation actors as well as match players.
- Power-up claims the normal pickup with melee. Time Dilation moves the actor, Accelerator repeatedly charges and fires at a normal-health opponent until the real damage/death system resolves a kill, then waits for the opponent's normal respawn; Decoherence activates the normal shield action. Shared damage values determine how many shots are needed.

Scenario data contains choreography/readability settings, not duplicate gameplay stats. If tuning makes a scenario impossible, it times out with a visible diagnostic in the Console and `LastFailure`; it does not count a successful loop or change the gameplay rules. New power-up types need a use sequence in the director.

## Lifetime and reset

The Hostile Constructs pane keeps every enemy root stationary. `HowToPlayEnemyDisplay` enables the Drone/Ranged Drone's native exhaust, drives Seeker charge/compression/thrust/recovery poses from the canonical Seeker prefab's timings, and cycles only the regular Dyson's native radial attack pose. The Ranged Drone repeats its canonical charge, three-shot burst and cooldown, using native panel/core animation and projectile speed, size and expiry. `Ranged Shot Travel` limits shots to its display column. Its owned projectile group has collision queries disabled and is destroyed when the pane exits. Seeker ghosts translate opposite a virtual tracking camera at gameplay lunge/glide speed; their line segments clip above the referenced SEEKER title plus its configurable clearance. The Seeker's fixed display position leaves room for its charging rear panels. These previews wait for native spawn draw-in and pane reveal, reset when disabled, and never enable targeting, collision or attack damage. The amplified Dyson retains its existing idle presentation.

Select the root of `03 Enemies.prefab` and use **How To Play Construct Stats** to adjust all seven constructs' Health, Attack, Speed, Range and Score bars. Each slider is a percentage of the available track width (0 hides the fill, 100 fills it). Values update immediately in the Inspector and support Undo/Redo and prefab overrides. Existing authored lengths are retained. Nonzero fills keep `HowToPlayStatBarIdle`, including bars changed from zero; the animation uses the selected length as its resting value. These settings change the instruction display only, not enemy gameplay tuning.

The carousel's combined Power-ups prefab places Particle Accelerator, Time Dilation and Decoherence from left to right. Its separate `How To Power-ups Time Dilation` scenario spawns the canonical Mass Nugget, Mass Nugglet, Amplifier Nugget and Amplifier Nugglet in order around a circle. The player follows the arcs through normal scripted movement and collects through body contact; pickup scales, spawn/despawn effects and rewards come from gameplay. `Circle Pickups`, `Pickup Circle Radius`, `Pickup Circle Leg Seconds` and `Pickup Spawn Pause` are editable on that scenario. The current pacing uses 0.65-second arcs and a 0.05-second spawn lead-in, flowing through each collection without stopping until the loop boundary. The bottom copy replaces the center column's controls. `ConfirmedBodyPickups` and `LastCollectedPickup` report actual collection callbacks. Demo collection is explicitly scoped to its owning player and applies the shared personal multiplier curve. Native `EnemyScoreToast` receipts show the actual mass restored and multiplier gained; mass-pickup score previews use the live reward table, personal multiplier and shared score math with a x1 team amplifier, without altering match totals. `ConfirmedPickupToasts` and `LastPickupToast` expose those receipts. Toasts use the demo camera and a session-owned pool; leaving the pane destroys its pickups and receipts together.

Each director owns one persistent actor group, initialized while inactive. Normal loops preserve the actor instances, health, mass, physics and cooldowns. Actors steer back through PlayerInputFrame; the director never teleports or replaces a visible actor to reset a loop. Accelerator's opponent uses the normal death/dissolve/respawn lifecycle at its original anchor. Pickups are reclaimed when effects expire, and receive their definition before OnEnable computes lifetime. Projectiles and impacts join the simulation group. Explicit Stop/restart or scene unload clears effects and inputs, deactivates the group and destroys it at frame end. Spawned pickup destruction is limited to the pickup, never the outer stage.

Simulation waits use scaled game time, matching Player actions. The existing visual effects retain their own time settings. This is state-driven choreography, not deterministic input replay; recorded inputs alone do not guarantee the same physics result across machines.

## Validation

- **MASSIVE > Demonstrations > Validate HOW TO Game Flow** exercises Attract, the carousel's timer/joystick navigation, gated Continue buttons, level selection, instructions, spawn/countdown, live movement/Attack/Shield/scoring, results and return in 1v1/NOVA and 2v2/HIGGS. It uses temporary Rewired controllers and isolated match-history files, shortens only runtime match clocks/NOVA finale waits, and restores the original Edit Mode scene and input settings. `HowToGameFlowValidation.Start(outputDirectory)` saves its report and screenshots to a chosen folder; the menu uses a unique temporary directory. Cabinet hardware and a packaged player build require separate checks.

- `HowToLayoutValidation.RunBatch` authors and exercises the six-pane layout in an isolated Unity project copy, checking repeated goals, blocks, Accelerator kill/respawn, shared actor sizing, shimmer, grid bindings, goal isolation and SFX suppression. It writes rendered views and `Library/HowToLayoutValidation/report.txt`. Do not run the authoring fixture against a working scene.

- **MASSIVE > Audio > Validate How To Play Silence** runs the actual scene with repeated SFX requests and newly created direct/play-on-awake sources, checks uninterrupted music and clean scene exit/re-entry, then restores Edit Mode. Results: `Library/HowToPlayAudioValidation/report.txt`.

- **MASSIVE > Demonstrations > Validate Prefabs and Tuning** checks canonical/nested references, components, ownership, roster slots, and shared tuning after temporary value changes; original values are restored.
- With How To Play open and saved, **Run How To Play** enters Play Mode. **Report Runtime Results** reports loop failures, confirmed blocks, pickup claims and fired projectiles.
- **MASSIVE > Player > Validate Player Tuning** exercises existing timing, handoff and shared/local tuning regression checks.
- **MASSIVE > Player > Validate Actor Scene Bindings** checks every level in the live Level Catalog, the development roster scenes and planar template, plus the missing-object fallback. Catalog levels must have enabled build scenes and exactly one valid roster, with spawn anchors visible through the arena masks. `PlayerActorMigrationValidation.StartPlayableCatalogRun(screenshotDirectory)` runs normal 1v1/2v2 startup and death/respawn for every catalog level in Play Mode and saves per-case screenshots and results. `StartRun` can target an individual scene (NOVA by default). Grid bindings are required only when a scene uses VectorGridGPU. These fixtures reload scenes and change only runtime timer/idle settings; exit Play Mode afterward.
- `RosterStartupValidation.StartRun(resultsPath)` injects missing/invalid bindings into disposable NOVA Play Mode instances, verifies actionable single-error rejection and closed scoring/input, and confirms unused 1v1 slots do not block startup. Expected error logs are included in the results file. No authored scene or prefab is saved.

`MassiveDemoMigration` contains the one-time prefab/scene migration and reference-preserving backups under `Library/DemoMigrationBackup`. Migration is already applied; ordinary authoring does not require rerunning it.


## Enemy Lab

`S-T_PLAYER-ACTIONS` now also contains **Enemy Lab**, enabled by default. On Play it pauses the match timer, suppresses the match roster and authored encounters, and suspends the Amplifier/Resonance spawner. Disable this root to use the existing Player Action Lab. Stopping the lab restores those prior states.

Six equally spaced columns reference the live Drone, Ranged Drone, Carrier, Particle Beam Turret, Seeker and Dyson Repulsor definitions and the canonical PlayerActor prefab. Enemy/player start markers and the loop count/timing are exposed per column. The turret mounts flush to the arena top wall; its existing beam reaches the unchanged player row. Enemy titles sit above the top border in the toast system's Input Mono Bold font at a smaller size. Column dividers are solid arena partitions; targeting, damage, projectile queries, swarm neighbors and physical actor contacts are also isolated by simulation scope.

Each loop demonstrates three attacks, one actual scripted player melee hit that kills the enemy, its ordinary death effect, a player walk back to its marker, and a fresh enemy with its native warning/assembly sequence. A Drone's three impacts are shielded to preserve it for the counterkill. The Carrier demonstrates three drone launches; Ranged Drone counts three complete bursts. A hit restores the demonstration player's lost mass so this can run indefinitely. One-hit defeat is an explicit runtime demonstration rule; enemy health/score assets and live-match damage are unchanged.

Use **MASSIVE > Demonstrations > Validate Enemy Lab** for the repeat-loop, target isolation, attack count, attributed counterkill and Dyson growth checks. Reports and rendered views go to `Library/EnemyLabValidation`. A failed choreography stops with a visible diagnostic instead of claiming a completed loop.

How To layout authoring writes world-space text through RectTransform anchored coordinates and records any prefab-instance overrides for controls and panel transforms. Validation reopens the saved scene before checking bounds or running demos, so an in-memory preview cannot conceal lost layout edits. The standalone Amplifier presenter takes its badge mesh/material from the canonical Core prefab and retains the normal shared font, layer order, masking and growth animation. `amplifierRespawnDelay` on the demonstration scenario shortens only the demo's capture-to-respawn wait (5 seconds); gameplay Cores keep their authored delay.
